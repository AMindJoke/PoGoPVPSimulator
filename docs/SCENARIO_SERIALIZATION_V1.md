# Scenario Review serialization v1

`PvPeakManualScenarioIO` owns the public, client-side Scenario Review document.
The canonical header is:

```json
{
  "schema": "pogo-pvp-scenario",
  "version": 1,
  "mode": "scenario-review"
}
```

The serializer exposes `serializeScenario`, `deserializeScenario`,
`validateScenario`, and `stableStringify`. Deserialization is the only entry
point used by Open and Import. It validates the complete document before the
application state is mutated.

## Top-level sections

- `capabilities`: format capabilities used for future additive evolution.
- `engine`: battle-engine compatibility metadata.
- `review`: review mode, segment state, replacement history, and timeline start.
- `participants`: semantic Pokémon A/B setup and current state, including form,
  shadow status, level, IVs, CP, moves, HP, energy, shields, stages, effects,
  and active/fainted status.
- `state`: exact resumable application/runtime state, Manual Mode decision
  state, pending Fast impacts, pending charged registration, and terminal result.
- `timeline`: semantic event history and its initial state. No DOM or rendered
  HTML is stored.
- `technicalIssues`: active reconstruction state plus stable IDs of technical
  timeline events. Resolved DRE/lag outcomes remain on their semantic events.
- `branchModel`: the current branch registry behind a versioned boundary. V1
  preserves current Undo/Redo behavior; the comparison model can evolve this
  section without coupling it to UI layout.
- `session`: root snapshot, canonical event snapshots, control mode, and the
  original runtime state required by restoration and Undo/Redo.

## Determinism and validation

Objects are recursively key-sorted before output, non-finite numbers and cyclic
values are rejected, and no export timestamp is generated by the serializer.
Validation covers schema/version, modes, Pokémon and move identifiers (when the
application catalog is supplied), numerical ranges, semantic event kinds,
pending Fast events, Technical Issue types, Manual Mode state, snapshots, and
the branch registry.

Invalid input returns `{ ok: false, errors, scenario: null }`. Open/Import do not
apply any state until this result is successful.

## Compatibility and exclusions

The v1 migration boundary accepts existing local/exported documents that use
`schemaVersion: 1` and converts them into the canonical shape. Future migrations
belong beside `migrateLegacyV1` in `manual-scenario-io.js`.

The document intentionally excludes DOM, open dialogs, bottom-sheet/tab state,
active timers, focus, hover/selection styling, and other presentation-only
state. Timeline zoom remains an ordinary application control in the exact
runtime snapshot, but it is not part of battle mechanics.
